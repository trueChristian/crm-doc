# Church policy, vocabulary, forms and approvals

Churches decide what qualifies for membership, which offices exist, how they certify a roll, which communications are optional, what counts as a quorum and when an expenditure needs a second signature. Record those decisions as effective-dated policy. Permit translated labels such as fellowship, assembly or parish to describe an underlying concept consistently in reports and exchanges.

| Record | Fields | Constraints and ownership |
| --- | --- | --- |
| SettingDefinition | id; key: immutable code; owner_area: code; value_type: type; allowed_values: optional set; default_value: typed; permitted_scopes: list; sensitivity: classification; requires_approval: boolean | One owner defines meaning, validation and fallback. Disallow unregistered keys, incompatible units and using free text as a permission expression. |
| PolicyVersion | id; definition_id → SettingDefinition; organization_id → Organization; optional congregation_id or campus_id; value: typed; revision: integer; valid_from, valid_until: instants; state: draft, scheduled, effective, retired; approval_ref: optional decision | One effective version per scope/key/instant. Definition states whether lower scopes may override. A candidate is previewed against affected records. |
| VocabularyTerm | id; organization_id; vocabulary: code; term_code: immutable code; parent_term_id: optional self ref; active_from, active_until: dates; sort_order: integer | Do not reuse retired codes with a new meaning. If changed terms affect eligibility, change the policy version as well. |
| TermTranslation | term_id → VocabularyTerm; locale: tag; short_label, full_label: text; explanation: optional text | One translation per term/locale. The display records its fallback language when the requested translation is missing. |
| FormDefinition | id; organization_id; purpose: code; owner_role: ref; title: localized text; scope: code; state: draft, published or withdrawn | One purpose can have several versions. Only a published version can accept new submissions. |
| FormRevision | id; form_id → FormDefinition; revision: integer; opens_at, closes_at: optional instants; visibility_rule: versioned predicate; completion_action: allowed workflow; privacy_notice_version: ref | A published revision is immutable. Old answers render with the questions asked at the time. |
| FormQuestion | id; form_revision_id; stable_key: code; input_kind: text, option, integer, amount, date, reference, file or acknowledgement; labels: localized text; constraints, allowed_options, show_when: typed definition; required_when_shown: boolean; sensitivity, retention_class: codes; display_order: integer | Rule dependencies cannot form cycles. Hidden questions are cleared from pending submissions and never block completion. Files require media/size checks. |
| FormSubmission | id; revision_id; applicant_person_id: optional Person; submitting_actor: actor; received_at: instant; operation_key: unique within form; status: received, in_review, accepted, returned or withdrawn; linked_record: optional scoped target | Public interest, account authentication and proof of a person's identity are separate. A form requesting membership starts an application. |
| FormAnswer | submission_id; question_id; value: validated typed value; visibility: classification; source_language: optional tag | One answer per question or an explicitly repeatable item. Staff can correct a value with amendment and reason. |
| DecisionRequest | id; target_type, target_id: scoped record; target_revision: version; policy_version_id; requested_by; requested_at; state: pending, approved, rejected, expired or superseded; due_at: optional instant | One or more DecisionStep rows. Material edits invalidate old approvals. Self-approval allowed only where the policy explicitly permits it. |
| DecisionStep | id; request_id; sequence: integer; required_role: ref; assigned_to: optional actor; quorum: integer; route: all, any or count; substitute_rule: optional policy; due_at: optional instant | Sequential steps open after predecessors pass. Simultaneous decisions lock the outcome once. |
| DecisionResponse | id; step_id; actor_id; action: approve, decline, recuse or return; reason: optional text; acted_at: instant; evidence: optional ref | A response belongs to one eligible actor and one version. An explicit superseding response preserves the first. |
| WorkflowTemplate / WorkflowStep | template id, owner_area, title, version, start_event, allowed_scope; step id, template_id, predecessor_ids, action_kind, assignee_rule, due_offset, stop_condition, failure_route | Publish only after cycle, permission and missing recipient checks. Freeze the version for running cases. An automation may prepare a request but cannot confer its own approval. |
| WorkflowRun / WorkflowTask | run id, template_version, subject_ref, operation_key, opened_at, closed_at, state; task id, run_id, step_id, assignee_ref, due_at, result, completed_by, completed_at, evidence_ref | Distinguish blocked, awaiting someone, completed, cancelled and failed. Retrying a failed dispatch does not repeat an earlier completed assignment. |

**Example.** A new-member form asks which congregation the guest attends. Choosing baptism preparation opens an additional question and a voluntary follow-up request. The secretary can return an incomplete form for correction. Acceptance creates one membership application linked to its source. A volunteer who can send the form cannot approve an admission or read a protected answer.

**Acceptance.** Two conflicting active quorum policies at the same scope cannot publish. A new translation has no effect on a historical vote. A reviewer who also submitted a restricted payment request is routed to another authorized reviewer. A voluntary checkbox initially appears unselected. A person withdrawing a form stops pending reminders and triggers the applicable retention workflow.
