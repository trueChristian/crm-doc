# Accept a recording into church custody

A congregation authorizes a service for live delivery on its own site. It may choose live only, a private archive with no replay, church-controlled storage, or managed capture and playback. The worship coordinator can identify the actual service and its permitted uses. The archive custodian checks the asset received from the selected provider. The editor clears a particular edition before the church can publish it.

| Scenario | Evidence the church should be able to inspect |
| --- | --- |
| Live only | Recording is disabled on each selected route. An automatic public replay feature that the provider cannot disable prevents use of that route for this service. A later request to publish requires separately authorized material. |
| Private archive, no replay | A captured asset enters restricted custody. Its arrival adds no player to a public calendar entry, no default audience and no permission to download. |
| Provider capture, church storage | Check the service, provider object/version, expected size or digest, recovery access and completeness of the church-held copy before selecting it for playback or giving up the source. A partial or conflicting copy remains unavailable for release. |
| Church capture, managed or church playback | Keep a stable source identity, approved custody and distinct release edition. Changing storage or player never changes a person's consent, a permitted audience or the publication period. |
| Notification unavailable | The clerk can record pending receipt and contact the custodian. A later callback is checked against the same church, service and session. A duplicated callback creates no second accepted master. |

## Acceptance run

1. Mark the end of the church service. Let the provider report capture completion after a delay. The resulting asset remains private while awaiting verification. Capture may be prohibited for a second service with the same title.
2. Interrupt transfer halfway and then change the remote object revision. The archive desk sees an incomplete transfer with a reason and independent recovery action. The CRM must not approve it for public use. Reconcile the revision with the custodian before accepting a replacement. The storage provider controls the transfer mechanics.
3. Accept a verified master into private custody. Approve only the sermon for public release. The release identifies the service occurrence, speaker permission, approved segments, language, audience and release dates. The restricted testimony, associated caption text and its identifying thumbnails stay off search and public pages.
4. Change the selected playback origin. Verify a permitted recipient can still access the same cleared edition. A public visitor requesting the protected master, an excluded audience or an expired edition sees no private content.
5. Withdraw the public edition while a downstream provider is unavailable. Block new church-controlled access, invalidate previews, notify the provider and assign an owner to its outstanding acknowledgement. Track observed downstream access separately. Record the withdrawal reason privately. The preservation decision and public release remain independently auditable.
