# Commerce and fundraising operations handbook

These manuals let a product owner, treasurer and department lead run the same scenario from different desks and compare the resulting balances, permissions and notices. Each amount belongs to an illustrative, explicitly stated policy. Select the church's effective accounting, recognition, tax and gift-acceptance policies before using an example for acceptance.

## How to use a case

Use the given organization, currency, timezone and policy assumptions as one isolated fixture. Set the actor and permitted campus. Enter events in the stated sequence, then repeat each operation where the scenario calls for replay. A handoff includes organization, authenticated source, unique business action and its revision, correlation with the original order or appeal, timestamps of occurrence and observation, currency/units, affected line or unit and authorization evidence. Reuse of the same key with different economic facts goes to review. Never accept an outside organization's identifier as authority over a local record.

Keep an evidence trail from approved promise to fulfilment, amount collected to reconciled settlement, and restricted source record to the exact public summary. Each team receives only the fields necessary to complete its task. A queue entry must identify its owner, failed operation, recoverable facts, permitted next action, deadlines and when the customer or donor was last informed. Reissue a document or a notification through the appropriate domain without creating a second economic event.

The [commerce specifications](../../commerce/README.md), [development specifications](../../development/README.md), [finance specifications](../../finance/README.md) and [ministry specifications](../../ministry/README.md) define the authoritative logical records. The scenarios use them directly. A retained approval or screenshot from a case is evidence about that case; it cannot authorize a later transaction.
