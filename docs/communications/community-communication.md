# Community communication

Some church communications need personal judgment and follow-through. A prayer list has a different audience from a sealed pastoral note. A phone tree reaches a member without internet. An emergency bulletin may need several updates before an all-clear. These features reuse the dispatch register and honor unsafe-contact restrictions across all routes.

## Everyday workflows

A member requests prayer for a relative. Intake asks what may be shared, with whom, for how long, whether a name may be included and whether a private pastoral response is desired. If permission for identifying the relative is absent, keep the intake restricted and consider genuinely non-identifying text for a suitable audience. Review even initials in a small community. Updating the private pastoral file does not republish anything. Withdrawal removes future sends and controlled online display. The steward can log any requested correction to recipients of an already distributed bulletin.

For the weekly bulletin the editor gathers service details, event notices, leadership announcements and approved community submissions. A proof lists items expiring before service day, missing translations, repeated announcements and any revised sources. Volunteers preparing paper copies see only the final authorized edition. A correction references the affected issue and the changing facts so an older printed copy can be recognized.

Activate a contact tree for a storm-related venue closure. The coordinator approves the wording and geographic scope, allocates reachable people to callers and estimates how many manual calls remain. An unavailable caller passes only their pending assignments to a permitted alternate. The coordinator can distinguish a confirmed conversation, voicemail, wrong number, unreachable person and request for assistance. A help request opens a separate restricted task, while the broad coordination screen shows only that follow-up is assigned. A call tree can run as a labelled rehearsal, with no public announcement or real-world escalation.

## Acceptance cases

- A request for the elders' prayer circle cannot be aggregated into a public prayer wall. A later permission extends only the specifically approved version and audience.
- A contact tree containing four assignments loses its caller after two confirmations. The alternate receives two pending calls. No one sees the former caller's full contact history.
- A crisis message warns the north campus of a closure. A later revision changes its venue and a final message declares normal service. Each recipient can identify the latest instruction. A retry cannot reissue an expired alert.
- A bulletin item expires during a print delay. The editor approves a refreshed issue or documents that already printed copies need correction. The event host, printer and portal can identify the same edition.
- A low-connectivity caller uses a limited, time-bound list and later records outcomes. Duplicate synchronized updates reconcile by assignment and timestamp and contested outcomes go to the steward.
